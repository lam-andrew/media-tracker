## V2 structure

- `apps/web`: React + TypeScript + Vite application, shared design tokens and reusable UI.
- `apps/api`: TypeScript API, provider integrations, server-side authorization.
- `packages`: shared media contracts/configuration where useful; preserve the generic media engine.
- `infra`: Docker Compose, container build/deployment configuration and operational guidance.
- `docs`: ADRs, architecture diagrams, setup, migration and deployment documentation.

PostgreSQL is the data foundation. ADR 0014 records the local Fastify/session implementation
and the auth work still needed before public deployment. External metadata requires internet.

Keep product naming centralized. Preserve the no-GitHub-issues workflow and existing quality,
security, documentation and review standards. Changes may land directly on the isolated v2
branch during initial setup; production promotion uses a reviewed PR and passing checks.

## First vertical slice

Design and implement search → preview → add → track, using Study 02 styling. Start with
real book search, sign-in, per-user saved items, status, half-star ratings, progress, and notes.
Provide immediate navigation feedback, cached revisits and optimistic edits with failure
recovery. Separate core page interaction from slow metadata enrichment. Measure on realistic
data and network conditions before expanding to movies, TV, games and the remaining v1 features.

The room and gallery are alternate presentations of the same library. Physical representations
for non-book media remain exploratory. Large-library browsing, keyboard/touch access, reduced
motion and contrast must work as well as the initial composition.

## Readiness before replacing v1

- User-reviewed visual design and core flows, including mobile, loading, empty and failure states.
- Existing features either migrated or explicitly agreed to be deferred; maintain a feature inventory.
- Verify authentication and per-user isolation, including server-side enforcement and recovery flows.
- Record measured navigation/interaction latency on the target environment; aim for feedback
  within roughly 100 ms while distinguishing server/API completion times.
- Rehearse account/data migration; preserve ownership, ratings, progress, notes and favorites.
- Run the app from reproducible containers with persistent storage, health checks and documented
  configuration. Verify backup restoration and operational rollback on the homelab.
- Pass appropriate automated checks and end-to-end validation on the candidate release.
- At cutover: preserve a v1 release, back up the database, control writes during final transfer,
  promote v2 through a reviewed PR, and remove obsolete v1 runtime code/dependencies/configuration.
  Database rollback must account for writes after cutover; an old container alone is insufficient.

Do not delete v1 data or switch the live deployment as part of workspace setup.
